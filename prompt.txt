Wat we bouwen
- Applicatie: LunchMonkeys – interne webapp om dagelijks lunchbestellingen te beheren.
- Rollen: admin en employee.
- Kernflows:
- Auth (domeinrestrictie @bluemonkeysit.nl), JWT, protected routes, admin-only acties. Frontend laat alleen lokale gebruikersnaam invullen; domein wordt automatisch toegevoegd. Server valideert dit eveneens.
  - Restaurants: CRUD + afbeelding (Cloudinary), website, optioneel menulink.
  - Orders: admin opent of sluit een dagorder; medewerkers voegen items toe (naam, notities, prijs). Realtime updates via Socket.IO (nieuwe order, order gesloten). Bij openen/sluiten krijgen alle gebruikers een notificatie met route naar de order.
  - Notificaties: lijst, mark as read, mark all as read, realtime bell-counter. Admins ontvangen automatisch een notificatie bij het uploaden van een bonnetje.
- Uploads: profielfoto (multipart/form-data, Cloudinary).
  - Wachtwoordbeleid: min. 12 tekens, ≥1 hoofdletter, ≥1 kleine letter, ≥1 cijfer, ≥1 speciaal teken; mag geen deel van naam of e‑mail bevatten; HIBP breach check (server-side) bij registreren en resetten.
  - Instellingen/Over: versie/build rechts in de header; “Laatste wijzigingen” (laatste 3 bullets uit version.json, nieuwste bovenaan). Mobiel: tekst niet afkappen; volledige tekst leesbaar (break-words).
  - Menu import (XML/JSON): we ondersteunen uploaden van een menuconfig (XML/JSON). Gebruik en onderhoud de bestaande documentatie (geen nieuwe .md-bestanden aanmaken; uitbreiden waar nodig in bestaande docs).

Stack 
- Backend: Node.js, Express, TypeScript, MongoDB (Mongoose), JWT, Socket.IO, helmet, compression, cors, express-rate-limit, swagger-jsdoc, swagger-ui-express.
- Frontend: React, Vite, TypeScript, React Router, axios, Tailwind, react-hot-toast.

API (indicatief; prefix /api)
- Auth: POST auth/register, POST auth/login, GET auth/me, POST auth/forgot-password, POST auth/reset-password.
- Users (admin): GET users, GET/PATCH users/{id}, PATCH users/{id}/role, PATCH users/{id}/status, POST users/{id}/reset-password, DELETE users/{id} (checks: geen zelfverwijdering/laatste admin).
- Restaurants: GET restaurants; POST/PATCH/DELETE restaurants (admin; upload image via Cloudinary).
- Orders: GET orders (filters status/date), POST orders (admin), GET orders/{id}, PATCH orders/{id} (close; admin), Items: POST/PATCH/DELETE orders/{id}/items.
- Notifications: GET notifications?unread=bool, PATCH notifications/{id}/read, PATCH notifications/read-all.
- Uploads: POST upload/profile (multipart/form-data).
- Health: GET health (status, versie, build, DB).

Release notes (belangrijk)
- version.json is de enige bron voor “Laatste wijzigingen”.
- Structuur: { version, buildNumber, lastUpdated, recentCommits }.
- recentCommits: max 5 entries (array van { date: 'YYYY-MM-DD', message: '...' }), nieuwste vooraan; oudste valt af; de volledige lijst wordt telkens herbouwd (nieuwe + resterende oudsten) om mergeconflicten te minimaliseren.
- App toont de laatste 3 (nieuwste eerst).
- Pipelines mogen recentCommits NIET overschrijven (geen git-log fallback).

Release notes flow
- Optie 3 (commit) in git-helper.ps1:
  - Vraagt: “Release notes + PR?”; zo ja: bullets → version.json updaten (max 5; volledige herschrijving) → commit (code + version.json) → push → PR.
  - Nee: alleen commit.
- Optie 4 (push):
  - Check uncommitted changes; zo ja: eerst committen.
  - Vraagt: “Deployment (release notes + PR)?”; ja: bullets → version.json updaten (max 5) → commit → push → PR; nee: alleen push.
- auto-pr.ps1:
  - Gebruikt bullets uit version.json van vandaag; ontbreken ze, vraagt éénmaal en schrijft terug naar version.json (max 5) + commit, en gebruikt dezelfde bullets in PR-description.
